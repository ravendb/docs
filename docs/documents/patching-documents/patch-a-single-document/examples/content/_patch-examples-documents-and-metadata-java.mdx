### Loading documents in a script

* Loading related documents from a patch script is supported only by the _defer_ or the _operations_ syntax.  
* The following example loads the product referenced by each order line and copies the product's current name to the order line.

<Tabs groupId='languageSyntax'>
<TabItem value="Session_defer_syntax" label="Session_defer_syntax">
```java
// Update each order line with the current name from its referenced product document
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript(
    "this.Lines.forEach(line => {" +
    "    var product = load(line.Product);" +
    "    if (product) {" +
    "        line.ProductName = product.Name;" +
    "    }" +
    "});");

session.advanced().defer(new PatchCommandData(
    "orders/1-A",  // id
    null,          // changeVector
    patchRequest,  // patch
    null));        // patchIfMissing

session.saveChanges();
```
</TabItem>
<TabItem value="Operations_syntax" label="Operations_syntax">
```java
// Update each order line with the current name from its referenced product document
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript(
    "this.Lines.forEach(line => {" +
    "    var product = load(line.Product);" +
    "    if (product) {" +
    "        line.ProductName = product.Name;" +
    "    }" +
    "});");

store.operations().send(new PatchOperation(
    "orders/1-A",   // id
    null,           // changeVector
    patchRequest)); // patch
```
</TabItem>
</Tabs>

### Patch document metadata

* A patch script can modify a document's metadata by accessing `this['@metadata']`.
* The following example sets `@expires` to one minute in the future.  
  When [document expiration](../../../../../server/extensions/expiration.mdx) is enabled, RavenDB deletes the document after this time is reached.
* Patching metadata with a script is supported only by the _defer_ or _operations_ syntax.

<Tabs groupId='languageSyntax'>
<TabItem value="Session_defer_syntax" label="Session_defer_syntax">
```java
// Schedule the document for expiration
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript("this['@metadata']['@expires'] = args.expires;");
// @expires must contain an ISO 8601 UTC date-time string
patchRequest.setValues(Collections.singletonMap("expires",
    NetISO8601Utils.format(DateUtils.addMinutes(new Date(), 1), true)));

session.advanced().defer(new PatchCommandData(
    "users/1",     // id
    null,          // changeVector
    patchRequest,  // patch
    null));        // patchIfMissing

session.saveChanges();
```
</TabItem>
<TabItem value="Operations_syntax" label="Operations_syntax">
```java

    "users/1",      // id
    null,           // changeVector
    patchRequest)); // patch
```
</TabItem>

### Add document

* Use the `put(documentId, document)` patch-script function to store another document.
* In this example:
  * The `projects/` prefix tells RavenDB to generate a new project ID.
  * `id(this)` returns the ID of the employee being patched and stores it in `ProjectLeader`.
  * `@metadata.@collection` places the new document in the `Projects` collection.
* Adding a document from a patch script is supported only by the _defer_ or the _operations_ syntax.

<Tabs groupId='languageSyntax'>
<TabItem value="Session_defer_syntax" label="Session_defer_syntax">
```java
// Create a project with a server-generated ID
// and reference the patched employee as its project leader
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript(
    "put('projects/', {" +
    "    ProjectLeader: id(this)," +
    "    ProjectDesc: 'New project'," +
    "    '@metadata': { '@collection': 'Projects' }" +
    "});");

session.advanced().defer(new PatchCommandData(
    "employees/1-A", // id
    null,            // changeVector
    patchRequest,    // patch
    null));          // patchIfMissing

session.saveChanges();
```
</TabItem>
<TabItem value="Operations_syntax" label="Operations_syntax">
```java

// and reference the patched employee as its project leader

    "});");

```
</TabItem>

### Clone document

* To clone a document from a patch script, pass the current document (`this`) to `put` with a new document ID.  
 The `employees/` prefix tells RavenDB to generate the clone's ID.
* Cloning a document from a patch script is supported only by the _defer_ or the _operations_ syntax.

<Tabs groupId='languageSyntax'>
<TabItem value="Session_defer_syntax" label="Session_defer_syntax">
```java
// Clone the current document under a new server-generated employee ID
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript("put('employees/', this);");

session.advanced().defer(new PatchCommandData(
    "employees/1-A", // id
    null,            // changeVector
    patchRequest,    // patch
    null));          // patchIfMissing

session.saveChanges();
```
</TabItem>
<TabItem value="Operations_syntax" label="Operations_syntax">
```java
// Clone the current document under a new server-generated employee ID
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript("put('employees/', this);");

store.operations().send(new PatchOperation(
    "employees/1-A", // id
    null,            // changeVector
    patchRequest));  // patch
```
</TabItem>
</Tabs>

<Admonition type="info" title="">

**Document data, related items, and revisions:**

* The clone receives a copy of the source document's body.
* Attachments, counters, and time series are stored separately and are not copied automatically.  
  The source document's revision history is not copied either.
* To manage related items from a patch script, use the predefined JavaScript methods:
  * [Counter methods](../../../../../server/kb/javascript-engine.mdx#counter-operations)
  * [Time series methods](../../../../../server/kb/javascript-engine.mdx#time-series-operations)
  * [Attachment methods](../../../../../server/kb/javascript-engine.mdx#attachment-operations)
* When [cloning a document via Studio](../../../../../studio/database/documents/create-new-document.mdx#clone-an-existing-document),  
  Studio copies the document body, attachments, counters, and time series.  
  It does not copy the source document's revision history.

**Archived documents:**

* If the source document is archived, the cloned document will not be archived.  
  See [Data archival overview](../../../../../data-archival/overview.mdx).

</Admonition>

### Delete document

* Use RavenDB's `del(documentId)` patch-script function to delete the document with the specified ID.
* The example below passes `id(this)` to delete the document currently being patched.
* Do not confuse `del(...)` with JavaScript's `delete` operator.  
  For example, `delete this.Extension` removes only the `Extension` property from the document.  
  See [Remove property](../../../../../documents/patching-documents/patch-a-single-document/examples/patch-examples-fields-and-arrays.mdx#remove-property).
* Deleting a document from a patch script is supported only by the _defer_ or the _operations_ syntax.

<Tabs groupId='languageSyntax'>
<TabItem value="Session_defer_syntax" label="Session_defer_syntax">
```java
// Delete the document currently being patched
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript("del(id(this));");

session.advanced().defer(new PatchCommandData(
    "employees/1-A", // id
    null,            // changeVector
    patchRequest,    // patch
    null));          // patchIfMissing

session.saveChanges();
```
</TabItem>
<TabItem value="Operations_syntax" label="Operations_syntax">
```java
// Delete the document currently being patched
PatchRequest patchRequest = new PatchRequest();
patchRequest.setScript("del(id(this));");

store.operations().send(new PatchOperation(
    "employees/1-A", // id
    null,            // changeVector
    patchRequest));  // patch
```
</TabItem>
