<Admonition type="note" title="">

* The C# client deserializes documents loaded from the server into entities using the
  [Newtonsoft.Json](https://www.newtonsoft.com/json/help/html/SerializingJSON.htm) library (also known as Json.NET).  
* Use the [conventions](../../../client-api/configuration/conventions.mdx) described in this article
  to customize the deserialization (e.g., to preserve document properties that your entity class does not define).  
* In this article:

  * [DeserializeEntityFromBlittable](../../../client-api/configuration/deserialization.mdx#deserializeentityfromblittable)  
  * [PreserveDocumentPropertiesNotFoundOnModel](../../../client-api/configuration/deserialization.mdx#preservedocumentpropertiesnotfoundonmodel)

</Admonition>

<Panel heading="CustomizeJsonDeserializer">

* The client uses `JsonSerializer` objects of the [Newtonsoft.Json](https://www.newtonsoft.com/json/help/html/SerializingJSON.htm)
  library to **deserialize** documents loaded from the server into entities.  
* Use the `CustomizeJsonDeserializer` convention to register an action that modifies only the `JsonSerializer` objects
  used to load documents (e.g., to keep a property's default value when the loaded document holds `null` for this property).  
  <br /><br />
  ```csharp
  Conventions =
  {
      Serialization = new NewtonsoftJsonSerializationConventions
      {
          CustomizeJsonDeserializer = serializer => throw new CodeOmitted()
      }
  }
  ```
  <br />
* Note that an action registered using [CustomizeJsonSerializer](../../../client-api/configuration/serialization.mdx#customizejsonserializer)
  also applies when loading documents, and runs before the `CustomizeJsonDeserializer` action.  
  A [converter](../../../client-api/configuration/serialization.mdx#adding-a-converter) registered using `CustomizeJsonSerializer`
  therefore does not need to be registered using `CustomizeJsonDeserializer` as well.

</Panel>

<Panel heading="DeserializeEntityFromBlittable">

Use the `DeserializeEntityFromBlittable` convention to customize entity
deserialization from a blittable JSON.

```csharp
Conventions =
{
    Serialization = new NewtonsoftJsonSerializationConventions
    {
        DeserializeEntityFromBlittable = (type, blittable) => throw new CodeOmitted()
    }
}
```

</Panel>

<Panel heading="PreserveDocumentPropertiesNotFoundOnModel">

* Some document properties are not deserialized to an object.  
* Set the `PreserveDocumentPropertiesNotFoundOnModel` convention to `true`
  to **preserve** such properties when the document is saved.  
* Set the `PreserveDocumentPropertiesNotFoundOnModel` convention to `false`
  to **remove** such properties when the document is saved.  
* Default: `true`  

```csharp
Conventions =
{
    PreserveDocumentPropertiesNotFoundOnModel = true
}
```

</Panel>

<Panel heading="DefaultRavenSerializationBinder">

Use the `DefaultRavenSerializationBinder` convention and its methods to
prevent gadgets from running RCE (Remote Code Execution) attacks while
data is deserialized by the client.

Read about this security convention and maintaining deserialization security
[here](../../../client-api/security/deserialization-security.mdx).

</Panel>

<Panel heading="Number Deserialization">

* RavenDB client supports all common numeric value types (including `int`, `long`,
  `double`, `decimal`, etc.) out of the box.  
* Note that although deserialization of `decimals` is fully supported, there are
  [server side limitations](../../../server/kb/numbers-in-ravendb.mdx) to numbers in this range.  
* Other number types, like `BigInteger`, must be handled using a [converter](../../../client-api/configuration/serialization.mdx#adding-a-converter).  

</Panel>
