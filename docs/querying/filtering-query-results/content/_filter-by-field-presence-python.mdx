<Admonition type="note" title="">

* Documents in the same collection can have different fields.  
  For example, a field added to newer documents might be missing from older documents.    
  You can optionally use [schema validation](../../../documents/schema-validation/overview.mdx) to require specific fields when documents are written.
    
* To filter documents by field presence:  
  * To find documents that **contain** a specified field, use `where_exists`.  
  * To find documents that are **missing** a specified field, use `.not_().where_exists`.  
  * Both are available through the [query API](../../../querying/overview.mdx#query-api).  

* An explicit `null` counts as **present** only when it is the value of the field you check.  
  If a parent on a nested path is missing or `null`, or the field is an empty array, the field counts as **missing**.  
  Learn more in [How field presence is determined](#how-field-presence-is-determined).
    
* You can check field presence when querying a **static index** or when making a **dynamic query**.  
  When querying a static index, the check applies to the fields produced by the index's map function.

* In this article:

### Dynamic query {/* #dynamic-query-existing-field */}

* Use `where_exists` to return documents that contain the specified field.  
  Documents that are missing the field are excluded from the results.

* RavenDB uses an auto-index to process the filter, creating one if needed.  
  Learn more about this query type in [Query a collection - with filtering](../../../querying/overview.mdx#2-query-a-collection---with-filtering).

* You can check field presence using either a **field name** or a nested **field path**, as shown below.
    
---    

<ContentFrame>

#### Filter documents by field name

The following query returns employees whose documents contain the `FirstName` field:

<Tabs groupId='languageSyntax'>
<TabItem value="Query" label="Query">
```python
employees = list(
    session.query(object_type=Employee)
    .where_exists("FirstName")
)
```
</TabItem>
<TabItem value="RQL" label="RQL">
```sql
from Employees
where exists("FirstName")
```
</TabItem>
</Tabs>

</ContentFrame>

<ContentFrame>

#### Filter documents by nested field path

You can also check for a nested field by specifying its full path.  
The following query returns employees whose documents contain `Latitude` at `Address.Location.Latitude`:

<Tabs groupId='languageSyntax'>
<TabItem value="Query" label="Query">
```python
employees = list(
    session.query(object_type=Employee)
    .where_exists("Address.Location.Latitude")
)
```
</TabItem>
<TabItem value="RQL" label="RQL">
```sql
from Employees
where exists(Address.Location.Latitude)
```
</TabItem>
</Tabs>

</ContentFrame>

### Static index query {/* #static-index-query-existing-field */}

* When querying a static index, use the **index-field name** in `where_exists`.  
  The index must include the field whose presence you want to check.

* The following index maps:
  * `FirstName` to an index-field with the same name.
  * `Address.Location.Latitude` to an index-field named `Latitude`.    
  * The document ID to an index-field named `Id`, to retain entries for documents with missing fields.  
    See [Static index query for missing fields](#static-index-query-missing-field) for details.

    ```python
    class Employees_ByFieldPresence(AbstractIndexCreationTask):
        def __init__(self):
            super().__init__()

            # The index-fields: Id, FirstName, Latitude
            # Include Id so documents with missing fields still have an index entry.
            self.map = """
            from employee in docs.Employees
            select new
            {
                Id = employee.Id,
                FirstName = employee.FirstName,
                Latitude = employee.Address.Location.Latitude
            }
            """
    ```
    
---

The following example queries the `Employees_ByFieldPresence` index and returns employee documents that contain the `FirstName` field:

<Tabs groupId='languageSyntax'>

```python

    session.query_index_type(Employees_ByFieldPresence, Employee)
```

### Dynamic query {/* #dynamic-query-missing-field */}

* Use `.not_().where_exists` to return documents that are missing the specified field.
* You can check for a missing field using either a **field name** or a nested **field path**, as shown below.

---
    
<ContentFrame>

#### Filter documents by field name

The following query returns employees whose documents do **not** contain the field `FirstName`:

<Tabs groupId='languageSyntax'>
<TabItem value="Query" label="Query">
```python
employees_without_first_name = list(
    session.query(object_type=Employee)
    .not_()
    .where_exists("FirstName")
)
```
</TabItem>
<TabItem value="RQL" label="RQL">
```sql
from Employees
where true and not exists("FirstName")
```
</TabItem>
</Tabs>

In RQL, `not` cannot appear immediately after `where`.  
Use `where true and not exists(...)` when the missing-field condition is the first condition.  
_session.query_ adds `true and` automatically in this case.

</ContentFrame>

<ContentFrame>

#### Filter documents by nested field path

Use the full path to check for a missing nested field.  
The following query returns employees whose documents do **not** contain `Latitude` at `Address.Location.Latitude`:

<Tabs groupId='languageSyntax'>
<TabItem value="Query" label="Query">
```python
employees_without_latitude = list(
    session.query(object_type=Employee)
    .not_()
    .where_exists("Address.Location.Latitude")
)
```
</TabItem>
<TabItem value="RQL" label="RQL">
```sql
from Employees
where true and not exists(Address.Location.Latitude)
```
</TabItem>
</Tabs>

</ContentFrame>

### Static index query {/* #static-index-query-missing-field */}

* Use `.not_().where_exists` with the **index-field name**.  
  The field you want to check must be included in the index's map function.

* The index must also retain an entry for documents that are missing that field.
  The index used in this article maps the document ID to `Id`, ensuring that an entry is retained even when both `FirstName` and `Latitude` are missing.
   
* **Alternatively**, set [Indexing.IndexEmptyEntries](../../../server/configuration/indexing-configuration.mdx#indexingindexemptyentries) to `true` to retain entries for documents that are missing all mapped fields,
  without needing to map `Id` for this purpose.    

<Admonition type="note" title="">

If [Indexing.IndexMissingFieldsAsNull](../../../server/configuration/indexing-configuration.mdx#indexingindexmissingfieldsasnull) is `true`,
missing mapped fields are indexed as `null` and count as **present**.  
Consequently, `.not_().where_exists` does not return documents whose missing fields were indexed this way.  
This setting does not affect auto-indexes.

</Admonition>

<Panel heading="How field presence is determined">

* `where_exists` checks field presence in the index used by the query:
  * An explicit `null` counts as **present** only when it is the value of the field you check.
  * If a parent on a nested path is missing or `null`, the field counts as **missing**.
  * An empty array counts as **missing**.

* These rules apply to both query types, with a configuration exception for static indexes:

  * **For dynamic queries**, they apply to the document field name or nested path specified in the query.

  * **For static index queries**, presence is checked on the fields produced by the index's map function.   
    For example, with the direct index-field mapping `Latitude = employee.Address.Location.Latitude`,  
    the query checks `Latitude`, not `Address.Location.Latitude`.

    If `Address` is missing or `null`, this mapping produces an implicit `null` for `Latitude`,  
    which is not indexed by default. The `Latitude` index-field therefore counts as **missing**.

    The [Indexing.IndexMissingFieldsAsNull](../../../server/configuration/indexing-configuration.mdx#indexingindexmissingfieldsasnull) configuration key is `false` by default.  
    If set to `true`, missing mapped fields are indexed as `null` and count as **present**.  
    Empty arrays still count as **missing**, regardless of this setting.

    For `.not_().where_exists` to return documents with missing fields, the index must retain entries for them.  
    See [Static index query for missing fields](#static-index-query-missing-field) for details.

---

The following examples use document field names and paths and assume the default indexing settings.  
For static indexes, they assume direct mappings and retained entries for documents with missing fields,  
as explained above.

| Document content                                  | Checked path                | `where_exists` result    | `.not_().where_exists` result |
| ------------------------------------------------- | --------------------------- | ------------------------ | ----------------------------- |
| `"FirstName": null`                               | `FirstName`                 | Document returned&nbsp;✅ | Document excluded&nbsp;❌      |
| No `FirstName` field                              | `FirstName`                 | Document excluded&nbsp;❌ | Document returned&nbsp;✅      |
| `"Territories": []`                               | `Territories`               | Document excluded&nbsp;❌ | Document returned&nbsp;✅      |
| `"Address": { "Location": { "Latitude": null } }` | `Address.Location.Latitude` | Document returned&nbsp;✅ | Document excluded&nbsp;❌      |
| `"Address": null`                                 | `Address.Location.Latitude` | Document excluded&nbsp;❌ | Document returned&nbsp;✅      |
| `"Address": { "City": "Seattle" }`                | `Address.Location.Latitude` | Document excluded&nbsp;❌ | Document returned&nbsp;✅      |

</Panel>

<Panel heading="Syntax">

### where_exists

```python
def where_exists(self, field_name: str) -> "DocumentQuery[_T]": ...
```

| Parameter      | Type  | Description |
|----------------|-------|-------------|
| **field_name** | `str` | For a dynamic query, the document field name or nested path.<br/>For a static index query, the index field name. |

---
    
### not_

The `not_()` method negates the next filtering condition.  
Place it immediately before `where_exists` to search for missing fields:

```python
.not_().where_exists("FirstName")
```

---
    
### RQL

```sql
// Find documents with the field.
where exists(FieldName)

// Find documents without the field.
where true and not exists(FieldName)
```
