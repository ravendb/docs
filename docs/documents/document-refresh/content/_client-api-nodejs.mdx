<Panel heading="Refreshing documents">

Using **document refresh**, you can schedule RavenDB to update a document at a set time.  
This way, features that react to document changes (e.g., indexes and ETL tasks) process the document once the set time has
passed, with no further action required from your application.

---

### The refresh process

1. **Enabling document refresh for a database:**  
   *Document refresh* is **disabled** by default. 
   See [Enabling document refresh](../../../documents/document-refresh/client-api.mdx#enabling-document-refresh) below.

2. **Scheduling a document's refresh:**  
   Add a `@refresh` property to the
   [metadata](../../../client-api/session/how-to/get-and-modify-entity-metadata.mdx) of the document you want to
   refresh, and set the property's value to the intended refresh time.  
   e.g., `"@refresh": "2026-12-01T08:00:00.0000000Z"`  
   See [Scheduling a document refresh](../../../documents/document-refresh/client-api.mdx#scheduling-a-document-refresh) below.

3. **Refreshing the scheduled document:**  
   The *document refresh* feature periodically checks the database for documents to refresh (every 60 seconds by default).  
   At the first check after the time set by the `@refresh` metadata property, the property is removed from the document's
   metadata, and the modified document is stored.  
   As a result, the document's [change vector](../../../server/clustering/replication/change-vector.mdx) is incremented,
   indicating that the document was updated.

4. **Processing the refreshed document:**  
   Features that react to document changes are triggered by this update and process the refreshed document.  
   For example:

   * The document is re-indexed by the indexes defined for the document's collection.
   * The document is replicated to the other nodes of the
     [database group](../../../server/clustering/distribution/distributed-database.mdx),
     and to the destinations of [external replication](../../../server/ongoing-tasks/external-replication.mdx) tasks.
   * An [ETL task](../../../server/ongoing-tasks/etl/basics.mdx) whose transformation script handles the document's collection
     runs the script over the document.
   * A [data subscription](../../../client-api/data-subscriptions/what-are-data-subscriptions.mdx) whose query matches the
     updated document sends the document to the subscription's worker (or to one of its workers, for a
     [concurrent subscription](../../../client-api/data-subscriptions/concurrent-subscriptions.mdx)).
   * If [revisions](../../../document-extensions/revisions/overview.mdx) are enabled for the document's collection, a new revision
     of the document is created.

5. **Rescheduling the document's refresh:**  
   Since the `@refresh` property is removed, the document is refreshed only once.  
   To refresh the document again, set the document's `@refresh` metadata property to a new time.

</Panel>

<Panel heading="Enabling document refresh">

To enable *document refresh* for a database, send the server a `RefreshConfiguration` object with its `disabled` property
set to `false`, using the
[ConfigureRefreshOperation](../../../documents/document-refresh/client-api.mdx#configurerefreshoperation) operation.

e.g., the following code enables *document refresh* and sets the interval between checks to five minutes.

```js
// Define the refresh configuration
const refreshConfiguration = {
    // Enable document refresh for the database
    disabled: false,

    // Check the database for documents to refresh every 5 minutes
    refreshFrequencyInSec: 300
};

// Send the configuration to the server
await store.maintenance.send(new ConfigureRefreshOperation(refreshConfiguration));
```
<br />

<Admonition type="note" title="">
On a secure server, enabling or configuring the *document refresh* feature requires, like other changes to a database's
configuration, a client certificate with `Admin` access to the database (or with an `Operator` or `Cluster Admin`
[security clearance](../../../server/security/authorization/security-clearance-and-permissions.mdx)).  
Setting a document's `@refresh` metadata property, on the other hand, is a change to the document, which `Read/Write` access
permits.  
See [Setting up Authentication and Authorization](../../../client-api/setting-up-authentication-and-authorization.mdx)
</Admonition>

The `RefreshConfiguration` object holds the following settings
(see [RefreshConfiguration](../../../documents/document-refresh/client-api.mdx#refreshconfiguration)):

* **`disabled`**  
  Set this property to `false` to enable *document refresh*, or to `true` to disable the feature.

* **`refreshFrequencyInSec`**  
  Sets the interval, in seconds, between the *document refresh* feature's checks for documents to refresh.

  <Admonition type="note" title="">
  The `refreshFrequencyInSec` value must be greater than 0: sending a value of 0 or less fails with an error named
  `RavenException`.  
  e.g., the following code sends a `refreshFrequencyInSec` value of 0 and catches the resulting error.

  ```js
  try {
      await store.maintenance.send(new ConfigureRefreshOperation({
          disabled: false,
          refreshFrequencyInSec: 0
      }));
  } catch (err) {
      if (err.name === "RavenException") {
          // The error's message includes:
          // "Refresh frequency for database '<database name>' must be greater than 0."
      }
  }
  ```
  </Admonition>

<Admonition type="note" title="">
On a [Community license](https://ravendb.net/buy), the *document refresh* feature cannot check for documents to refresh more
often than every 36 hours (129600 seconds).  
Enabling *document refresh* with a lower `refreshFrequencyInSec` value fails with an error named `LicenseLimitException`.  
e.g., the code above, which sets `refreshFrequencyInSec` to 300, fails on a Community license.
</Admonition>

</Panel>

<Panel heading="Scheduling a document refresh">

To schedule a document's refresh, set the `@refresh` metadata property of the document to the intended refresh time, and save
the document.

<Admonition type="warning" title="">
The `@refresh` metadata property is reserved for the *document refresh* feature.  
Do not use it for any other purpose: RavenDB reads any value set for this property as a refresh time.  
A valid date and time schedules the document's refresh, and any other value makes saving the document fail.
</Admonition>

e.g., the following code schedules a refresh of the `users/1-A` document for one hour from now.

```js
const session = store.openSession();

// Load the document
const user = await session.load("users/1-A");

// Set the document's refresh time to one hour from now, in UTC
const refreshTime = new Date(Date.now() + 60 * 60 * 1000);
session.advanced.getMetadataFor(user)["@refresh"] = refreshTime.toISOString();

// Save the document
await session.saveChanges();
```
<br />

* **Setting the refresh time in UTC:**  
  Set the `@refresh` property to a UTC date string (e.g., `refreshTime.toISOString()`).  
  `toISOString()` returns the time in UTC with a `Z` suffix, which marks the time as UTC, so the server reads the intended time
  correctly.  
  e.g., `"@refresh": "2026-12-01T08:00:00.000Z"`

  <Admonition type="note" title="">
  Do not set the property to a date string without a time zone designator (e.g., `"2026-12-01T08:00:00"`).  
  The server reads such a value as the server machine's local time.  
  If the client machine and the server machine are in different time zones, the document will be refreshed at a different
  time than intended.
  </Admonition>

* **Setting an invalid refresh time:**  
  If the value of the `@refresh` property is not a valid date and time, `saveChanges` throws an error named `RavenException`,
  and none of the session's changes are saved.

* **Scheduling while *document refresh* is disabled:**  
  Setting the `@refresh` property while *document refresh* is disabled for the database still schedules the document's refresh.  
  Once the feature is enabled, documents whose refresh time has already passed are refreshed, starting at the feature's first
  check.

* **Changing or canceling a scheduled refresh:**  
  To change a document's refresh time, set its `@refresh` property to a new time and save the document.  
  To cancel the refresh, remove the `@refresh` property from the document's metadata using a
  [patch](../../../documents/patching-documents/patch-a-single-document/api-overview.mdx).  
  e.g., `await store.operations.send(new PatchOperation("users/1-A", null, PatchRequest.forScript("delete this['@metadata']['@refresh'];")));`

### ConfigureRefreshOperation

Sends a `RefreshConfiguration` object to the server, to enable or disable *document refresh* for a database and configure the
feature.

```js
new ConfigureRefreshOperation(configuration)
```
<br />
Usage:

```js
const result = await store.maintenance.send(new ConfigureRefreshOperation(refreshConfiguration));
```
<br />

| Parameter | Type | Description |
|-----------|------|-------------|
| **configuration** | `RefreshConfiguration` | The *document refresh* configuration to apply to the database. See [RefreshConfiguration](../../../documents/document-refresh/client-api.mdx#refreshconfiguration). |

| Return value | |
|-----------|-------------|
| `ConfigureRefreshOperationResult` | Contains `raftCommandIndex`. See [ConfigureRefreshOperationResult](../../../documents/document-refresh/client-api.mdx#configurerefreshoperationresult). |

</ContentFrame>
