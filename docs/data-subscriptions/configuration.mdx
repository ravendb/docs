# Data subscriptions: Configuration

<Panel heading="Configuration keys">

The following keys control data subscription behavior. Each can be set server-wide or per database.

<ContentFrame>

### Subscriptions.ArchivedDataProcessingBehavior

The default processing behavior of data subscriptions for archived documents.  
A subscription applies this behavior **in addition** to the subscription's query, so the query cannot select documents that the behavior excludes.  
e.g., if a subscription's processing behavior is `ExcludeArchived` and the subscription's query selects only archived documents,
the subscription sends no documents to the worker.

- **Type**: `enum ArchivedDataProcessingBehavior`:
   * `ExcludeArchived`: the subscription selects only non-archived documents.
   * `IncludeArchived`: the subscription selects both archived and non-archived documents.
   * `ArchivedOnly`: the subscription selects only archived documents.
- **Default**: `ExcludeArchived`
- **Scope**: Server-wide or per database

<Admonition type="note" title="">
* A subscription takes this key's value when the subscription is created, unless you set the subscription's own handling of archived documents (see [Client API](../data-subscriptions/creating-subscription/creating-subscription_api.mdx#archived-documents) or [Studio](../data-subscriptions/creating-subscription/creating-subscription_studio.mdx#defining-the-subscription-task)).  
  A later change to the key does not affect existing subscriptions.
* A subscription to [document revisions](../data-subscriptions/revisions-support.mdx) **ignores** this key and sends the revisions of archived and non-archived documents alike.
* On a [sharded database](../sharding/subscriptions.mdx#unsupported-features), all subscriptions use this behavior, and a subscription's own setting has no effect.  
  Unlike on a non-sharded database, a later change to the key **does** affect existing subscriptions.
</Admonition>

</ContentFrame>

<ContentFrame>

### Subscriptions.MaxNumberOfConcurrentConnections

The maximum number of concurrent subscription connections allowed per database.

- **Type**: `int`
- **Default**: `1000`
- **Scope**: Server-wide or per database

</ContentFrame>
