<Admonition type="note" title="">

* **RVN013** reports RavenDB queries that materialize results with `ToList`, `ToArray`, `ToListAsync`, or `ToArrayAsync`,  
  or register lazy execution with `Lazily` or `LazilyAsync`, without an explicit result bound.

* **Default severity**: _Info_  
  **Automated code fix**: _No_

<Panel heading="Description">

RavenDB applies no default limit to query results.  
When a query does not specify a page size, the server returns all matching results in a single call  
(see [Paging query results](../../indexes/querying/paging.mdx)).

Without `Take(n)`, the number of results depends on the data:  
a query that returns a few documents against test data can return an entire collection in production,  
and `ToList` or `ToArray` loads every result into memory.

`Lazily()` and `LazilyAsync()` register a query for later execution.  
They delay execution but do not limit how many results the query retrieves when it runs.

By default, when a query returns more than 2048 results, the server raises a ["Page size too big"](../../monitoring/alerts-and-notifications/performance-hints.mdx#paging) performance hint.

</Panel>

<Panel heading="Trigger condition">

<ContentFrame>

### When is RVN013 reported?

RVN013 checks calls to `ToList()`, `ToArray()`, `ToListAsync()`, `ToArrayAsync()`, `Lazily()`, and `LazilyAsync()`,  
with or without arguments, made on a RavenDB query.
The diagnostic highlights the method name, such as `ToList` or `Lazily`.
    
---    
    
**Query types checked**:

- **LINQ queries**:  
  queries that start from `session.Query<T>()`, in sync and async sessions,  
  including after standard LINQ operators such as `OfType<T>()`, `Select`, and `GroupBy`.  
  Queries written with `from … select …` and queries held in local variables are also checked.
        
- **Document queries**:  
  queries that start from `session.Advanced.DocumentQuery<T>()` or `session.Advanced.AsyncDocumentQuery<T>()`.
            
- **Raw queries**:  
  queries that start from `session.Advanced.RawQuery<T>(query)` or `session.Advanced.AsyncRawQuery<T>(query)`,  
  when the RQL argument is a compile-time string constant that does not contain the word `limit`.  
  This includes constant interpolated strings, such as `$"from Orders"` or `$"from {Collection}"` when `Collection` is a `const string`.

- **Queries created elsewhere**:  
  RVN013 also checks RavenDB queries passed into the current method, stored in fields or properties, or returned by helper methods.  
  However, it cannot detect a `Take()` call or RQL `limit` clause applied where those queries were built,  
  so it may report queries that are already bounded. See [Limitations](#limitations).

---
                
**Where RVN013 looks for `Take()`**:

The call is reported when the query has no `Take()` call in any of these places:

- The method chain before the checked call, including the source of a query-syntax `from` clause,  
  such as `from o in session.Query<Order>().Take(10) select o`.
- The initializer of a local variable that holds the query.
- An assignment to that local variable that appears before the checked call in the same method,  
  such as `query = query.Take(10);`.

RVN013 treats any `Take()` call in one of these places as an explicit bound, including `Take(int.MaxValue)`.

</ContentFrame>
<ContentFrame>

### When is RVN013 not reported?

- `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`, `Any`, `Count`, `LongCount`, and their async forms.  
  They return a single result or value.

- Raw queries that RVN013 can trace back, through the method chain or a local-variable initializer, to a `RawQuery` or `AsyncRawQuery` call
  whose RQL argument contains the word `limit` (case-insensitive) or is not a compile-time string constant.
  Nonconstant arguments include a non-`const` variable, a parameter, a method result, and an interpolated string with a nonconstant hole.

- LINQ over results already loaded into memory,  
  such as the second `ToList()` in `session.Query<Order>().Take(10).ToList().Where(…).ToList()`.

</ContentFrame>

</Panel>

<Panel heading="How to resolve">

- In LINQ queries and document queries, call `.Take(n)` before the checked call.
- In raw queries, add a `limit` clause to the RQL.
- To retrieve all results, [page through them](../../indexes/querying/paging.mdx#paging-examples) with `Skip()` and `Take()`,  
  or [stream](../../querying/stream-query-results.mdx) them instead of loading them all into memory.  
  If the result set is known to be small, `Take(int.MaxValue)` states that retrieving all results is intentional.

---

### Before (triggers RVN013)

```csharp
var orders = session.Query<Order>()
    .Where(x => x.Company == "companies/1-A")
     // Triggers RVN013: no Take(), so every matching order is returned.
    .ToList();
```
<br/>

### After (correct)

```csharp
var orders = session.Query<Order>()
    .Where(x => x.Company == "companies/1-A")
    .Take(50)
    .ToList();
```
<br/>

### Document queries and raw queries

```csharp
// Document query: bounded by Take()
var orders = session.Advanced.DocumentQuery<Order>()
    .WhereEquals(x => x.Company, "companies/1-A")
    .Take(50)
    .ToList();
```

```csharp
// Raw query: bounded by a 'limit' clause in the RQL
var orders = session.Advanced
    .RawQuery<Order>("from Orders where Company = $company limit 50")
    .AddParameter("company", "companies/1-A")
    .ToList();
```
<br/>

### Retrieving all results

```csharp
var query = session.Query<Order>()
    .Where(x => x.Company == "companies/1-A");

// Stream the results: each result is read from the stream one at a time.
using var stream = session.Advanced.Stream(query);
while (stream.MoveNext())
{
    Order order = stream.Current.Document;
    // Process the order...
}
```

```csharp
// The result set is known to be small: state that retrieving all results is intentional.
var orders = session.Query<Order>()
    .Where(x => x.Company == "companies/1-A")
    .Take(int.MaxValue)
    .ToList();
```

<Panel heading="Limitations">

- Only `ToList`, `ToArray`, `ToListAsync`, `ToArrayAsync`, `Lazily`, and `LazilyAsync` are checked.  
  Other ways to retrieve all results, such as iterating the query in a `foreach` loop,  
  `ToDictionary`, or `AsEnumerable().ToList()`, are not reported.
    
- A `Take()` applied outside the method is not detected.  
  A query typed as `IRavenQueryable<T>`, `IDocumentQuery<T>`, or another RavenDB query type is reported when it is received as a parameter,
  read from a field or property, or returned by a method, even if it was bounded where it was created. For example:

  ```csharp
  IDocumentQuery<Order> GetRecentOrders(IDocumentSession session) =>
      session.Advanced.DocumentQuery<Order>()
          .OrderByDescending(x => x.OrderedAt)
          .Take(50);

  // RVN013 is reported on ToList, although GetRecentOrders applies Take()
  var orders = GetRecentOrders(session).ToList();
  ```

  A raw query received this way is reported regardless of its RQL text, even when the RQL contains `limit` or is not a compile-time string constant.
    
  A value typed only as `IQueryable<T>` is checked when RVN013 can trace its receiver chain or a local-variable initializer back to a RavenDB query.
  An `IQueryable<T>` parameter, field, or property is not checked, and neither is the result of a method called outside the query chain, such as `GetOrders()` in `GetOrders().ToList()`.
    
- Conditions are not evaluated.  
  An earlier assignment containing `Take()` inside an `if` block suppresses RVN013 even if the block does not run,  
  while a `Take()` inside a conditional expression, such as `flag ? query.Take(10) : query`, is not detected.
    
- RVN013 does not evaluate query conditions or grouping.  
  A query whose result size is limited by its condition, such as `Where(x => x.Id == id)` or `Where(x => x.Id.In(ids))`, or a `GroupBy` over a fixed set of values, is still reported.  

  For simple document retrieval by ID, consider `Load()` or `LoadAsync()`.  
  Otherwise, make the query's known upper bound explicit with `Take()`; for example, `Take(ids.Length)` for a query restricted to those IDs.
  Alternatively, suppress RVN013 for that call.
    
- When RVN013 can trace a raw query back to its `RawQuery` or `AsyncRawQuery` call, `limit` is matched anywhere in the RQL text,
  so a query that uses `limit` only as a field name or inside a string value is not reported.

  For these queries, nonconstant interpolated RQL is not checked, even when only a filter value is interpolated.
  For example, `$"from Orders where Company = '{company}'"` is not reported when `company` is a nonconstant variable.

  RVN013 does not inspect RQL in assignments made after a local variable's declaration.  
  When it cannot locate the `RawQuery` or `AsyncRawQuery` call, it reports the checked call unless it finds a `Take()`
  in one of the places listed under [When is RVN013 reported?](#when-is-rvn013-reported).

</Panel>

<Panel heading="Related C# analyzers">

* [RVN012](./RVN012.mdx)  
  Reports independent loads and materializing queries on the same session that can be sent in a single request using the lazy API.  
    
  Its code fix converts queries to `Lazily()` or `LazilyAsync()`. RVN013 checks these calls too,
  so an unbounded query is still reported at the `Lazily` or `LazilyAsync` method name.  
    
  Add `Take()` before the lazy registration to resolve it.
